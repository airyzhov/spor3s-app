## 4. Гриб = отчёт за неделю

Блок `RoadMap.tsx:1127–1185` (дневной чек-ин) заменяется на единую точку входа в недельный отчёт. Отдельная кнопка «💾 Сохранить прогресс недели N» (1699–1725) убирается — гриб становится единственным входом, форма метрик (1467–1581) переезжает под гриб как раскрывающаяся часть карточки.

Состояния гриба:

| Условие | Вид | Текст |
|---|---|---|
| Курс не начат | 🍄 приглушённый, некликабельный | «Начни курс — и открой еженедельные отчёты (+25 SC)» + скролл к блоку старта курса |
| Неделя N доступна | 🍄 активный, пульсирует | «Собери отчёт за неделю N → +25 SC» |
| Форма раскрыта | 🍄 + 4 слайдера + заметка | кнопка «Сдать отчёт за неделю N → +25 SC» |
| Отчёт сдан, следующая неделя позже | ✅ | «Неделя N откроется 23.08» |
| Месячный лимит исчерпан | 🍄 активный | после отправки: «Неделя N сохранена (без SC — лимит 100 SC/мес)» |

Бэкенд не меняется: тот же `POST /api/survey` с тем же телом (`memory`, `sleep`, `energy`, `stress`, `note`). Ответ уже содержит `week`, `scEarned`, `scLimitReached`, `currentBalance`.

Дополнения к API — бонус за цель месяца (§5) и приём стартовой самооценки (§4.1).

### 4.1 Стартовая самооценка — встроена в старт курса

Сейчас это отдельный экран, который ранним `return` перекрывает всю вкладку и при этом ничего не сохраняет (`RoadMap.tsx:527`, `handleStartAssessment` пуст). Переделываем: самооценка становится **шагом внутри старта курса**, а не самостоятельным экраном.

Флоу: тап по «1 / 3 / 6 мес.» → в той же карточке раскрываются 4 слайдера «Отметь, как сейчас» → кнопка «Начать курс». Рядом — «Пропустить» (курс стартует без нулевой точки). Отдельный экран и `showStartAssessment` как блокирующий `return` удаляются.

Хранение — та же таблица `surveys`, запись с `data: { week: 0, kind: 'baseline' }`:

- `POST /api/survey` принимает `baseline: true` → пропускает проверки недель и месячного лимита, **SC не начисляет**, пишет `week: 0`.
- `surveysWithWeeks()` (`survey/route.ts:10`) сейчас теряет нулевую неделю: `Number(0)` ложно, и запись переедет в неделю 1. Нужна явная ветка: `if (row?.data?.kind === 'baseline') return { row, week: 0 }`, а подбор `targetWeek` по-прежнему стартует с 1.
- В графике истории нулевая точка рисуется как «Старт» — появляется честное «было → стало».
- SC за неё нет: это не источник дохода, а база для сравнения. В цель месяца не попадает автоматически, потому что счёт отчётов идёт по транзакциям (§5).

## 5. Цель месяца

**Правило:** 4 недельных отчёта внутри одного календарного месяца → разовый бонус **+50 SC**.

Реализация — новый модуль `lib/monthGoal.ts`:

```ts
export const MONTH_GOAL = { reportsTarget: 4, scTarget: 100, bonus: 50 };
export function monthKey(d = new Date()): string;               // "2026-08"
export async function getMonthGoal(userId): Promise<{
  reportsDone: number; scEarned: number; bonusPaid: boolean;
}>;
export async function grantMonthGoalIfComplete(userId): Promise<number>; // 0 или 50
```

- `reportsDone` = число транзакций `sc_transactions` с `source_type='survey'` за текущий календарный месяц. Считаем по транзакциям, а не по строкам `surveys`: стартовая самооценка (§4.1) SC не даёт и в счёт не идёт автоматически, а в `POST /api/survey` этот запрос уже выполняется для месячного лимита (`survey/route.ts:107`) — лишних обращений к БД нет.
- Начисление через `creditSC({ sourceType: 'month_goal', description: 'Цель месяца — 4 отчёта за месяц (2026-08)' })`.
- **Идемпотентность:** перед начислением проверяем `sc_transactions` по `source_type='month_goal'` в запросе, уже ограниченном текущим месяцем (`created_at >= monthStart`). Через `source_id` не получится: при реализации выяснилось, что колонка имеет тип **uuid**, строка `"2026-08"` туда не пишется — вставка падала бы молча (`creditSC` не проверяет ошибку insert), баланс всё равно рос бы, а бонус начислялся бы повторно при каждом вызове. Тот же приём для одноразовых бонусов без естественного uuid уже используется в `app/api/subscribe-bonus/route.ts`. Миграции не нужны.
- Вызов: в конце `POST /api/survey`, после успешного `creditSC` за отчёт. Ошибка бонуса не должна валить сохранение отчёта → в `try/catch`, в ответ добавляем `monthGoalBonus: number`.
- Бонус в лимит 100 SC/мес по отчётам **не входит** (другой `source_type`).

UI в Кабинете — блок над грибом:

```
🏆 Цель месяца: ██████░░  2 из 4 отчётов
   Собери 4 отчёта до 31 августа → +50 SC
```

После получения: `✅ Цель месяца выполнена — +50 SC. Новая цель с 1 сентября`.

Граница месяца считается по времени сервера (как и существующий месячный лимит в `survey/route.ts:106`) — отдельную работу с таймзонами не вводим.

## 8. Агрегирующий API `/api/home-summary`

Витрине нужны данные из 3 источников (`user-level`, `referral-stats`, статус подписок ×3 = 5 запросов). Для главного экрана в Telegram-вебвью на плохой сети это дорого → один эндпоинт.

`GET /api/home-summary?user_id=` →

```jsonc
{
  "sc": 120, "totalEarned": 220,
  "level": { "code": "collector", "name": "🌿 Собиратель", "icon": "🌿",
             "progress": 0.4, "scToNext": 180, "nextName": "🌳 Эксперт" },
  "friends": 3, "referralEarned": 250, "referralCode": "@user",
  "tasks": { "done": 0, "total": 3, "left": 3, "bonusPerTask": 30 },
  "monthGoal": { "reportsDone": 2, "reportsTarget": 4, "bonus": 50, "bonusPaid": false }

```

- Источники: `user_levels`, `referrals`, `sc_transactions` (`subscribe_*`, `referral_cashback`, `month_goal`), `surveys`, `getLevelInfo()` из `levelUtils`.
- Статус заданий читается одним запросом по `source_type IN ('subscribe_telegram','subscribe_youtube','subscribe_instagram')` (+ легаси `coin_transactions`, как в `check-subscription-status`).
- **Гость/фоллбек-юзер** (id не UUID: `guest-*`, `test-*`, `temp-user`) → сразу нули и `tasks.left = 3`, без обращений к БД (та же защита, что в `check-subscription-status:17`).
- Ошибка запроса не ломает главный экран: витрина рендерится с нулями и не показывает плашку заданий.

## 11. Риски и техдолг

1. **Инфляция уровней.** 250 SC/мес → Легенда за 4–5 месяцев по SC. Сдерживают требования по сумме заказов, но при активной покупке юзер упирается в потолок уровней быстро. Решение не входит в этот запуск; если через 2 месяца видим упор — поднимаем пороги или добавляем 6-й уровень.
2. **Двойной вход в приложение.** `app/page.tsx` (живой, рендерит `AppClient`) и `app/(client)/page.tsx` (дубль со своей копией логики + `MushroomTracker`). Все изменения делаем в `AppClient`/`RoadMap`; дубль надо удалить отдельной задачей.
3. **Первый отчёт требует старта курса.** Курс стартует только при оплаченном заказе (`start-course/route.ts:36`). Значит без покупки заработать можно только задания (90 SC) и рефералку. Это осознанно: гриб для новичка — витрина мотивации, а не источник SC.
4. **Граница месяца по времени сервера.** Пользователь в другой таймзоне может увидеть смену цели месяца не в полночь по своему времени. Принято как есть.
5. **`monthGoal` считается за календарный месяц**, а недели курса — от даты старта. В месяце с 5 отчётными неделями цель закрывается на 4-м отчёте, 5-й идёт уже без бонуса (и без SC из-за лимита 100/мес). Ожидаемое поведение.
6. **Нулевая неделя ломается на текущем парсере.** `surveysWithWeeks()` трактует `week: 0` как «не задано» и переносит запись в неделю 1 — стартовая самооценка молча съест первый отчёт. Ветку для `kind: 'baseline'` нужно добавить до любого сохранения baseline, иначе повредим данные ранних пользователей.
