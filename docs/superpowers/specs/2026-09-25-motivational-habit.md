# Мотивационная привычка

Дата: 2026-09-25
Статус: сделано по просьбе владельца («привычку надо сделать»). Пока видна только в тестовом режиме (`lib/testers.ts`).

## 1. Что это

Награда уровня 🌿 Собиратель (100 SC и хотя бы один заказ). Человек выбирает привычку на 4 недели — из готового списка или свою — и раз в неделю отмечает, получилось ли. За каждую неделю с «получилось» — **+25 SC**, за привычку до **100 SC**. Это совпадает с тем, что панель SC обещает с августа: «🌟 Мотивационная привычка — до 100 SC/мес» (`SC_MECHANICS.motivational_habit`).

## 2. Правила (`lib/habit.ts`)

| Что | Как |
|---|---|
| Длительность | 4 недели от момента старта (`started_at`), неделя — ровно 7 суток |
| Отчёт | один за неделю и только за идущую; номер недели считает сервер |
| Пропущенная неделя | прошла без отчёта — отметить её уже нельзя (`skipped`) |
| «Получилось» | +25 SC в `sc_transactions`, `source_type = habit_week`, `source_id` = id отчёта |
| «Не получилось» | отчёт сохраняется, SC нет |
| Конец | прошли 4 недели или сдан отчёт за 4-ю — можно выбрать новую привычку; старая гаснет (`is_active = false`) |
| Одна за раз | новую поверх идущей не начать |
| Доступ | уровень ≥ Собиратель, считается от SC и заказов (как панель SC и окно уровней), а не от флага `has_motivational_habit` |

Отличия от старого кода, который так и не запускался: он давал +5 SC за объяснение, почему не получилось, и +20 SC бонуса за полный месяц. От этого отказались, чтобы привычка давала ровно обещанные «до 100 SC». Кроме того, в старом коде неделя не сдвигалась (отчёт всегда уходил за 1-ю), все недели можно было отметить разом, а закончившаяся привычка не давала начать новую.

## 3. Данные (`motivational_habits.sql`)

- `predefined_habits` — готовые привычки. 10 штук засеяно; список правится прямо в таблице, `is_active = false` прячет строку.
- `user_habits` — привычка пользователя.
- `weekly_habit_reports` — отчёты; `unique (habit_id, week_number)` не даёт сдать неделю дважды, даже если два запроса пришли одновременно.

RLS включён без политик: доступ только у сервера (service role). Владелец выполняет файл в Supabase → SQL Editor один раз. Пока таблиц нет, API отвечает `tableReady: false`, а карточка пишет «скоро».

## 4. API и интерфейс

- `GET /api/motivational-habit?user_id=` — доступ, идущая привычка со статусом недель, готовые привычки.
- `POST { action: 'start', name }` — начать; `POST { action: 'report', is_completed, note? }` — отчёт за идущую неделю.
- Карточка `components/MotivationalHabit.tsx` в кабинете: замок с тем, чего не хватает до Собирателя; выбор привычки; идущая привычка с четырьмя неделями (✅ ❌ — ● ○), кнопки «✅ Получилось +25 SC» / «❌ Не получилось» и необязательный комментарий. Если отчёт за неделю уже сдан — когда откроется следующий. Если привычка закончилась — итог и выбор новой. После начисления панель SC перечитывает баланс.

## 5. Что дальше

Показать привычку всем — это часть общего запуска геймификации (`SHOW_GAMIFICATION`), решение владельца. Напоминания в боте о недельном отчёте в этот объём не входят.
