# История SC: поиск в админке, история в кабинете, сообщения в боте

Дата: 2026-09-30
Статус: согласовано в чате («да, делай» 30.09)

## 1. Цель

- Владелец в админке быстро находит человека по нику или Telegram ID, начисляет или списывает SC
  и видит всю историю его SC.
- Покупатель видит свою историю SC в кабинете.
- Бот пишет покупателю о каждом начислении и списании SC.

Проверено по базе 30.09: 61 операция у 23 человек (максимум 6 на человека), у всех есть описание,
списания записаны с минусом, легаси-таблица `coin_transactions` пуста, у всех 165 строк `user_levels`
баланс равен сумме операций в `sc_transactions`. Значит, история из `sc_transactions` полностью
объясняет баланс.

## 2. Правила (ответы владельца)

- Поиск в «💰 Начислить SC» вместо выпадающего списка: часть ника (без учёта регистра и @) или часть
  Telegram ID; до 8 совпадений, у каждого ник, имя, ID и баланс; выбор кликом, Enter — первый;
  выбранный — отдельной строкой с балансом и «сменить»; без выбранного «Начислить» не работает.
- История SC выбранного — под формой: новые сверху, начисления зелёные, списания красные, ручные
  операции помечены «вручную», номера заказов сокращены до 8 знаков; после начисления обновляется.
- Комментарий к ручной операции видит покупатель (в боте и в истории) — подпись под полем.
  Галочка «Уведомить в боте» (по умолчанию включена) — для тихих исправлений.
- Кабинет: раздел «🧾 История SC» под панелью SC, сворачивается как «Мои заказы», в заголовке —
  число операций; нет операций — раздела нет.
- Бот: сообщение при каждом изменении SC — задания, опрос, привычка, цель месяца, SC за оплаченный
  заказ, списание при заказе, приветственный бонус, 5% с заказа друга, ручные операции.
  Кнопка «🧾 История SC» открывает кабинет сразу на истории. Пишем только на числовой Telegram ID;
  отказ Telegram (не запускал бота) не мешает начислению. На первое задание придут два сообщения:
  «+30 SC» и напоминание про «Участвую» в розыгрыше — это нормально.

## 3. Решение

### Общие функции без базы — `lib/scHistory.ts`

- `type ScTransaction = { id, created_at, amount, description, source_type }`;
- `formatScAmount(amount)` → `+30`, `−50` (знак минус U+2212);
- `shortOrderIds(text)` → `#<uuid>` превращается в `#<первые 8 знаков>`;
- `scDateLabel(iso)` → `28.09 14:02` по Москве;
- `SC_HISTORY_APP_URL = 'https://ai.spor3s.ru/?open=sc'`;
- `scChangeNotice({ amount, description, balance }, telegramId)` → `TelegramNotice | null`:
  `💰 <b>+30 SC</b> — описание` (списание — `💸`), вторая строка `Баланс: <b>N SC</b>`, описание
  с экранированным HTML и сокращёнными номерами заказов, кнопка `🧾 История SC` (web_app).
  `null` — нет числового Telegram ID или сумма 0.

### Сервер

- `lib/scHistoryServer.ts`: `getScHistory(userId, limit = 100)` — операции человека, новые сверху.
- `lib/scNotify.ts`: `notifyScChange(userId, { amount, description, balance })` — Telegram ID из
  `users`, `scChangeNotice`, `sendTelegramNotice`. Нет токена бота — ничего не делает; любые ошибки
  ловит и пишет в лог, наружу не пробрасывает.
- `lib/telegramSend.ts`: запрос к Telegram обрывается через 5 с (`AbortSignal.timeout`) — теперь
  сообщение уходит из начисления SC, и зависший Telegram не должен держать ответ.
- `lib/scLedger.ts` — операции, которые раньше жили прямо в маршрутах:
  - `manualAdjustSC({ userId, amount, description, notify })` — ручная операция из админки
    (запись `manual`, `earned`/`spent`, баланс и `total_sc_earned`/`total_sc_spent` как раньше).
    Пустой комментарий → «Начисление от магазина» или «Списание магазином». `notify: false` —
    без сообщения. Возвращает новый баланс.
  - `spendScForOrder({ userId, orderId, coins, balanceBefore, spentBefore })` — списание при
    заказе (`order_discount`), затем сообщение. Ошибка записи или баланса — в лог, без сообщения.
- `creditSC` (`lib/referral.ts`) после обновления баланса вызывает `notifyScChange` — этим
  покрыты задания, опрос, привычка, цель месяца, SC за заказ, приветственный бонус и кэшбэк.
- Маршруты: `/api/admin/manual-coin` принимает `notify` и вызывает `manualAdjustSC`;
  `/api/order` вызывает `spendScForOrder`.
- API истории: `GET /api/sc-history?user_id=` (кабинет; не UUID — пустой список, как у розыгрыша)
  и `GET /api/admin/sc-history?user_id=` (пароль админки; не UUID — 400). Ответ
  `{ transactions: ScTransaction[] }`.

### Админка

- `lib/adminSearch.ts`: `pickUsers(users, query, limit = 8)` → `{ matches, total }` (пустой
  запрос — никого), совпадение — как у `matchesUser`.
- `app/admin/UserPicker.tsx` — поле поиска, список совпадений («ещё N — уточните поиск»,
  «Никого не нашли»), строка выбранного.
- `app/admin/ScHistoryAdmin.tsx` — история выбранного (заголовок «🧾 История SC — N операций»).
- `app/admin/page.tsx`: `UserPicker` вместо `<select>`, подпись под комментарием, галочка
  «Уведомить в боте», кнопка неактивна без выбранного, после начисления — перечитать балансы
  и историю.

### Кабинет

- `lib/course.ts`: `cabinetFocusFromUrl` понимает `?open=sc`.
- `app/(client)/ScHistorySection.tsx` — раздел на `CabinetSection` (`storageKey`
  `spor3s_sc_history_open`), данные `/api/sc-history`, перечитывается по `refreshKey`.
- `RoadMap.tsx`: раздел сразу под `ScStatus`; фокус `sc` раскрывает его и прокручивает к нему
  (тот же механизм, что у курса). `AppClient.tsx` — тип фокуса.
