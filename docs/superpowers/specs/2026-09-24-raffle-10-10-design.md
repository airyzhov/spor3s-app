# Розыгрыш 10.10

Дата: 2026-09-24
Статус: согласовано в чате (условия и три уточнения — ответы владельца от 24.09)

## 1. Цель

Промо-розыгрыш, который приводит новых пользователей и подписчиков: на главном экране — кнопка «🎁 Розыгрыш 10.10» с условиями и личным прогрессом, в админке — учёт участников, выгрузка таблицы и выбор трёх победителей по команде владельца (он записывает экран).

## 2. Правила

| Что | Значение |
|---|---|
| Друзья засчитываются с | 24.09.2026 00:00 GMT |
| Приём заявок до | 10.10.2026 включительно, 23:59:59 GMT (граница — `2026-10-11T00:00:00Z`, не включая) |
| Итоги | 12 октября, по кнопке владельца в админке |
| Победителей | 3, шансы у всех участников равные |
| Кнопка на главной | прячется через неделю после итогов (`2026-10-19T00:00:00Z`) |

**Условия участия** проверяются автоматически, записываться не нужно:

1. **Задание:** хотя бы одно из трёх подписочных заданий кабинета выполнено и SC получены — строка `sc_transactions` с `source_type` из `subscribe_telegram / subscribe_youtube / subscribe_instagram`, созданная до конца приёма. Задания, выполненные до старта розыгрыша, тоже считаются (каждое выполняется один раз).
2. **Друг:** хотя бы один друг, который:
   - пришёл по реферальной ссылке участника в окне розыгрыша — строка `referrals` (`referrer_user_id` = участник), `created_at` ∈ [старт, конец приёма);
   - новый: его запись `users` создана не раньше чем за 10 минут до строки `referrals` (бот создаёт её по клику на ссылку); уже знакомые приложению люди не засчитываются;
   - настоящий пользователь Telegram: `telegram_id` — только цифры;
   - открыл приложение: у него есть строка `ai_agent_status` (её пишет `/api/init-user` при входе в мини-апп; бот её не пишет).

**Приз победителя** зависит от его собственных друзей на момент итогов:

| Друзей | Приз |
|---|---|
| 1–3 | 1 добавка на выбор |
| 4–5 | 2 добавки на выбор |
| 6 и больше | комплекс добавок |

## 3. Кнопка на главной

Компонент `app/(client)/RaffleBanner.tsx`, рендерится в `AppClient` на шаге 2 («Каталог») над `HomeStatus`. Данные — `GET /api/raffle?user_id=`.

Свёрнуто: `🎁 Розыгрыш 10.10 — выиграй добавки` и справа статус («✅ Ты участвуешь» / «1 из 2 условий»). Тап раскрывает:

- призы по таблице §2 и «3 победителя»;
- список условий с отметками ✅/⬜: задание (кнопка «К заданиям» → кабинет, блок заданий) и друг (счётчик «Друзей: N», кнопка «Пригласить друга»);
- текущий приз: «Если выиграешь — 1 добавка. Пригласи ещё 3 — будет 2 добавки»;
- сроки: «Приём до 10 октября включительно (23:59 GMT — 02:59 11 октября по Москве). Победителей выберем 12 октября».

Состояния по времени:

| Стадия | Когда | Что видно |
|---|---|---|
| `open` | до конца приёма | условия, прогресс, кнопки |
| `closed` | приём закрыт, итогов нет | «Приём закрыт, победителей выберем 12 октября» + свой статус |
| `drawn` | итоги сохранены | «🏆 Победители: @a — 2 добавки, …» |
| `hidden` | после 19.10 | ничего |

Гость (открыл не через Telegram, id не UUID или `telegram_id` не цифры): условия и приписка «Участвовать можно только через Telegram — открой приложение из бота @spor3sbot», без прогресса. Имя победителя на главной: `@логин`, без логина — «участник …1234» (последние 4 цифры Telegram ID).

## 4. Починка реферальной ссылки на главной

`HomeStatus` сейчас шарит `t.me/spor3sbot?start=@логин` (или телефон), а бот (`tg-bot/bot.ts`, `bot.start`) засчитывает приглашение только по `start=<числовой telegram_id>`. Приглашения с главной не записывались, а телефон ещё и создавал фиктивного «заочного» пригласившего.

Новый модуль `lib/referralLink.ts`: `referralLink(telegramId)` → `https://t.me/spor3sbot?start=<id>` только для цифрового id, иначе `null`; `referralShareUrl(telegramId)` → ссылка `t.me/share/url` с тем же текстом, что сейчас. `/api/home-summary` отдаёт `telegramId` (только цифровой), `HomeStatus` и `RaffleBanner` строят ссылку через модуль. Кнопка приглашения скрыта, если ссылки нет. Ссылка кабинета (`RoadMap`) уже правильная — не трогаем.

## 5. Админка

Компонент `app/admin/RaffleAdmin.tsx`, раздел «🎁 Розыгрыш 10.10» над заказами. Данные — `GET /api/admin/raffle`.

- Сводка: участников (оба условия), всего с каким-либо прогрессом.
- Таблица: логин, Telegram ID, заданий, друзей, участвует ✅/—, приз при победе. Сначала участники, потом остальные. Общее поле поиска админки фильтрует и её (`matchesUser`).
- «⬇️ Скачать таблицу» — CSV для Excel: разделитель `;`, UTF-8 с BOM, `GET /api/admin/raffle?format=csv` (заголовок `x-admin-secret`, поэтому скачивание через `fetch` → blob).
- «🎲 Выбрать 3 победителей»:
  - до конца приёма кнопка неактивна: «Доступно после 10.10, 23:59 GMT»;
  - после — `POST /api/admin/raffle/draw`. Сервер берёт снимок участников, выбирает победителей (`crypto.randomInt`, тасование Фишера — Йетса) и **сохраняет** до ответа. Клиент показывает анимацию для записи экрана: ~2,5 с перебор имён участников, затем по одному три победителя с призами;
  - если итоги уже есть — показываем их с датой; «Переиграть» только через подтверждение (`force: true`), каждая попытка — новая строка, история остаётся;
  - участников меньше трёх — побеждают все, кто есть; ноль — сообщение, ничего не сохраняем.
- Если таблицы итогов нет в базе — вместо кнопки подсказка: «Выполни `raffle_draws.sql` в Supabase → SQL Editor».

## 6. Данные

Новая таблица — файл `raffle_draws.sql` в корне (как остальные SQL проекта; владелец выполняет его в Supabase SQL Editor один раз, до 12.10):

```sql
create table if not exists raffle_draws (
  id uuid primary key default gen_random_uuid(),
  raffle_id text not null,
  drawn_at timestamptz not null default now(),
  participants jsonb not null,
  winners jsonb not null
);
create index if not exists raffle_draws_raffle_idx on raffle_draws (raffle_id, drawn_at desc);
alter table raffle_draws enable row level security;
```

RLS без политик — доступ только у сервера (service role). Текущий итог — последняя строка по `drawn_at`. Участники в отдельную таблицу не пишутся: считаются на лету из `sc_transactions`, `referrals`, `users`, `ai_agent_status`, снимок сохраняется вместе с итогами.

## 8. Ошибки

- Любая ошибка `/api/raffle` → кнопка не показывается (главный экран не ломается), как у `HomeStatus`.
- Гостевые id (не UUID) — прогресс не считается; в базу идёт только запрос итогов (он нужен всем, чтобы знать стадию).
- Нет таблицы `raffle_draws` → итоги `null`, в админке подсказка про SQL; главная работает (стадии `open`/`closed`).
- Розыгрыш до конца приёма → 400. Повтор без `force` → 409 с сохранёнными итогами.
